Portfolio, GitHub and Resume for Data Roles

Turn your learning into evidence employers trust. Choose three to five portfolio projects, structure them on GitHub with strong READMEs, publish dashboards and apps, write an ATS-friendly one-page resume with quantified bullets, and optimise LinkedIn and Naukri profiles for analyst, data scientist, data engineer and GenAI roles.

What hiring managers look for

Target role Must-have evidence
Data / business analyst SQL case study, Excel model, Power BI dashboard, EDA with recommendations
Data scientist EDA, A/B test analysis, ML model with business threshold, explainability

Pick 3–5 projects (from this handbook)

  1. SQL: end-to-end sales case study (SQL lesson 15).
  2. Power BI: Adventure Cycles dashboard with DAX and drill-through (Power BI capstone).
  3. Python EDA: telecom churn EDA with recommendations (Python lesson 22) or retail analytics capstone (Python lesson 29).
  4. ML: churn prediction with profit-based threshold and SHAP (ML lesson 28).
  5. GenAI: NovaMart RAG support assistant with evaluation and guardrails (GenAI lessons 5, 9, 12).

Make at least one project your own: a dataset from data.gov.in, Kaggle or your workplace (anonymised) about a domain you care about.

README template: Problem (one paragraph, business framing) → Data → Approach (bullets) → Results (numbers + one chart) → Recommendation → How to run → Next steps. Put a live link (Streamlit Cloud, Hugging Face Spaces, Power BI publish-to-web with sample data, Tableau Public) at the top.

Resume: one page, quantified

Weak bullet Strong bullet
"Worked on churn analysis using Python." "Built a churn model (ROC-AUC 0.80) and targeting rule that reaches 2.3× more churners than random outreach, worth ≈₹60K/month in saved margin."
"Made Power BI dashboards." "Designed a Power BI sales dashboard (star schema, 25 DAX measures) used weekly by 4 regional managers; cut reporting time from 6 hours to 30 minutes."
"Know SQL." "Wrote 40+ SQL queries (CTEs, window functions) to analyse 6,300 orders; identified tables/bookcases as loss-making due to >20% discounts."

Formula: action verb + what you did + tool + measurable result. Sections: header (name, city, phone, email, LinkedIn, GitHub, portfolio), summary (2 lines, target role), skills (grouped), projects/experience, education, certifications. Use a simple single-column layout (ATS systems mis-read tables and graphics), PDF format, and mirror keywords from the job description honestly.

LinkedIn and job portals

  • Headline: "Data Analyst | SQL · Power BI · Python | Turning sales data into decisions".
  • About: 3 short paragraphs: who you are, what you build (link projects), what you are looking for.
  • Featured: pin your best project and dashboard. Post a short write-up per project (problem, chart, insight).
  • Naukri/Instahyre: complete every field, update weekly (recency boosts ranking), set salary and notice period honestly.
Key takeaways
  • Choose 3–5 projects that match the target role and show business impact.
  • Publish on GitHub with clear READMEs, charts and live demos.
  • One-page ATS-friendly resume; every bullet = action + tool + quantified result.
  • Keep LinkedIn and portals complete, keyword-aligned and active.

SQL patterns you must know

Python
import duckdb, pandas as pd
sales = pd.read_csv("superstore_sales.csv", parse_dates=["order_date"])
print(duckdb.sql("""
-- Top 2 products by sales in each region (window function)
WITH r AS (
  SELECT region, product_name, SUM(sales) AS sales,
         RANK() OVER (PARTITION BY region ORDER BY SUM(sales) DESC) AS rnk
  FROM sales GROUP BY region, product_name)
SELECT region, product_name, ROUND(sales) AS sales FROM r WHERE rnk <= 2 ORDER BY region, rnk;
""").df())

-- Month-over-month growth with LAG
WITH m AS (SELECT DATE_TRUNC('month', order_date) AS month, SUM(sales) AS sales FROM sales GROUP BY 1)
SELECT month, ROUND(sales) AS sales, ROUND(100.0 * (sales - LAG(sales) OVER (ORDER BY month)) / LAG(sales) OVER (ORDER BY month), 1) AS mom_pct
FROM m ORDER BY month DESC LIMIT 4;
""").df())

Pattern Typical question
GROUP BY + HAVING Customers with more than 5 orders
Joins (inner, left, anti) Customers who never ordered
Window: ROW_NUMBER/RANK Top N per group, de-duplicate latest record
Window: LAG/LEAD, running SUM Growth, retention, cumulative totals
CASE WHEN Buckets, conditional counts, pivots
Date functions Monthly cohorts, days between events
Self join / recursive CTE Manager hierarchy, consecutive days

Approach out loud: clarify the table grain → write the query step by step (CTEs) → check edge cases (NULLs, ties, duplicates) → validate with a small count.

Excel and Power BI questions

Question Short answer
VLOOKUP vs XLOOKUP vs INDEX-MATCH? XLOOKUP looks left/right, has defaults and exact match by default; INDEX-MATCH works in older versions; VLOOKUP breaks when columns move
Pivot table vs Power Pivot? Power Pivot uses a data model with relationships and DAX measures across tables
Calculated column vs measure (DAX)? Columns are computed row by row and stored; measures are evaluated in filter context at query time
What does CALCULATE do? Evaluates an expression in a modified filter context
Star schema? Fact table of events joined to dimension tables; simpler, faster models
Import vs DirectQuery? Import copies data (fast, scheduled refresh); DirectQuery queries the source live (fresh, slower)
Row-level security? Roles with DAX filters so users see only their rows

Statistics and experiments

Be ready to explain: mean vs median, standard deviation, distributions, correlation vs causation, confidence intervals, p-values, Type I/II errors, sample size and A/B test pitfalls (peeking, SRM, novelty). See ML lessons 1–6 for model answers.

Case questions: a framework

  1. Clarify the metric and time frame. 2. Check data quality first. 3. Segment (where is the drop?). 4. Form hypotheses (internal vs external). 5. Validate with data. 6. Recommend action and how you would measure it.

Product-sense metrics: define a north-star metric, input metrics and guardrails (e.g. for a food-delivery app: weekly ordering customers; conversion, delivery time, order value; cancellations, complaints).

Behavioural: STAR

Situation (context) → Task (your goal) → Action (what you did, with tools) → Result (numbers, learning). Prepare 6 stories: a project you are proud of, a mistake you fixed, a conflict, a tight deadline, influencing without authority, learning a new tool fast.

Practice resources

W3Schools SQL quiz and exercises, LeetCode SQL 50, HackerRank SQL, StrataScratch, DataLemur, Kaggle Learn; mock interviews with peers; time yourself (15 minutes per medium SQL question).

Key takeaways
  • Master SQL patterns: aggregation, joins, window functions, CTEs, dates; think aloud and check edge cases.
  • Know Excel lookups/pivots and Power BI modelling, DAX, CALCULATE, star schema and RLS.
  • Explain statistics and A/B testing simply.
  • Use a structured framework for metric and product cases.
  • Prepare STAR stories with quantified results.

Python and pandas (quick answers)

Question Answer
List vs tuple vs set vs dict? Mutable sequence / immutable record / unique unordered / key→value; sets and dicts give O(1) lookups
apply vs vectorisation? Vectorised column operations run in C and are much faster; avoid apply(axis=1) on large data
merge vs join vs concat? merge on columns, join on index, concat stacks
How to handle missing values? Understand why, then drop, impute (median, group-wise, model) or flag; impute inside CV
Generator vs list? Generators are lazy and memory-efficient, consumed once

Statistics and ML fundamentals

Question Model answer
Bias-variance trade-off? Simple models underfit (bias), complex models overfit (variance); choose complexity by validation error
L1 vs L2? L1 zeroes coefficients (selection); L2 shrinks smoothly; Elastic Net mixes
Why cross-validation? A single split is noisy; k-fold averages and supports tuning without touching the test set
Precision vs recall? Precision: flagged that are right; recall: positives caught; choose by error costs
ROC-AUC vs PR-AUC? PR-AUC is more informative for rare positives
Bagging vs boosting? Parallel averaging (variance) vs sequential error correction (bias)
How does gradient descent work? Iteratively step weights against the loss gradient with a learning rate
What is data leakage? Using information unavailable at prediction time; prevent with pipelines, time-based splits and feature cut-offs
p-value? Probability of data at least this extreme if H0 were true; not the probability H0 is true

ML system design: a template

Example: "Design a fraud detection system for UPI payments." Real-time decision under 100 ms; label = confirmed fraud (delayed, imbalanced); features: amount vs user history, device/location change, merchant risk, velocity, graph links; model: gradient boosting + rules + anomaly scores; evaluate PR-AUC and recall at alert capacity; serve with a feature store and low-latency API; monitor drift and attack patterns; human review queue; A/B test thresholds.

LLM, RAG and agent questions

Question Model answer
How do LLMs work? Transformers trained to predict the next token, then instruction-tuned and aligned with feedback
RAG vs fine-tuning? RAG for changing knowledge with citations; fine-tuning for behaviour/format
How to evaluate a RAG system? Retrieval hit rate/MRR + answer correctness, faithfulness, abstention on a labelled set
How to reduce hallucinations? Grounding, tools, "say I don't know", citations, validation, evaluation
What is an agent? An LLM in a loop choosing tool actions toward a goal, with memory and stopping conditions
What is MCP? Open protocol to connect assistants to tools/data via servers (tools, resources, prompts)
Prompt injection defence? Separate data from instructions, least-privilege tools, approvals, output checks
Cost control? Model routing, caching, batching, shorter context and outputs

Take-home assignments

  1. Restate the problem and assumptions in the first lines of your report.
  2. Do a focused EDA; do not chart everything.
  3. Baseline first, then 1–2 better models; validate correctly.
  4. Translate results into business impact and a recommendation.
  5. Clean, runnable code (requirements, README); a 5-slide summary.
  6. State limitations and next steps honestly.

Live coding tips

Clarify inputs/outputs and edge cases, start with a simple correct solution, test with a small example, then optimise and state Big-O (Python DSA lessons 26–28).

Key takeaways
  • Answer concisely, then go deeper only if asked.
  • Use the design template: goal → metric → data → features → model → serving → monitoring.
  • Know LLM/RAG/agent trade-offs, evaluation and safety.
  • Take-homes: baseline, correct validation, business recommendation, clean code, honest limitations.

Text
Hi <Name>, I'm a data analyst (SQL, Power BI, Python) who built <project link> on <domain>.

Track everything in a simple sheet: company, role, date, source, status, next step, notes.

Salary and offers

Research ranges on AmbitionBox, Glassdoor, LinkedIn Salary and peers for your city and experience. Ask for the full CTC breakdown (fixed, variable, joining bonus, benefits), negotiate on evidence (skills, competing offers, market data), and compare learning opportunities, team quality and growth, not only salary.

First 90 days in the job

  1. Learn the business: products, customers, key metrics and their definitions.
  2. Find the data: sources, owners, known quality issues; document as you go.
  3. Deliver a small, useful win in the first month.
  4. Communicate: weekly updates, clear charts with insight titles, assumptions stated.
  5. Automate repetitive reports; share reusable SQL and notebooks.
  6. Keep learning: one new skill per quarter (dbt, cloud, experimentation, GenAI).
Key takeaways
  • Follow the 90-day roadmap with a weekly routine of learn, build, share, practise and apply.
  • Run the job search as a funnel with referrals, tailored applications and tracking.
  • Negotiate with market data and evaluate the whole offer.
  • In the new role, learn the business, deliver early wins, communicate clearly and keep learning.
