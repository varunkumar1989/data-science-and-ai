What is Tableau?

Tableau is a visual analytics platform: you drag fields onto shelves and Tableau writes the query, aggregates the data and draws the chart. It is owned by Salesforce and, with Power BI, is one of the two BI tools most often named in Indian analyst job posts. Where Power BI leans on DAX formulas and the Microsoft stack, Tableau is known for fast visual exploration and highly customisable charts.

Tableau Desktop Full authoring tool; saves locally, connects to databases Paid (Creator licence)

TipWhich one should you install?

Learners should install Tableau Public (free). It has almost every authoring feature of Desktop. The two limits: workbooks are saved to your public profile (so never use confidential data) and it connects mainly to files (Excel, CSV, text, JSON, PDF, spatial) and Google Sheets rather than company databases. Your public profile also works as a portfolio for interviews.

The workspace

Dimensions vs measures, discrete vs continuous

Tableau sorts every field in two ways, and the colour of a pill tells you which:

Meaning Example What it creates
Dimension Categories you slice by Region, Category, Customer Name Groups (one mark per value)
Measure Numbers you aggregate Sales, Profit, Quantity SUM, AVG, COUNT…
Discrete (blue pill) Separate values Region, YEAR(Order Date) as "2023, 2024" Headers
Continuous (green pill) An unbroken range SUM(Sales), exact date Axes

A measure dropped into the view is aggregated (default SUM). Right-click the pill → Measure to switch to Average, Median, Count, Count (Distinct), Minimum, Maximum, Standard deviation and so on.

Common mistakesBeginner mistakes
  • Saving confidential company data to Tableau Public: everything there is public.
  • Sending a .twb file: the receiver cannot open it without your data. Send .twbx.
  • Leaving a date as a string ("Abc"): you lose drill-down and date functions. Change the type on the Data Source page.
  • Using a measure that should be a dimension (e.g. Postal Code as SUM): right-click → Convert to Dimension.

Interview cornerQuestions you may be asked

Q: What is the difference between a dimension and a measure? A dimension is a categorical field used to group the data (Region, Category); a measure is a numeric field that Tableau aggregates (SUM of Sales). Each mark represents one combination of the dimensions in the view.

Q: Discrete vs continuous? Discrete fields (blue) create headers and distinct colours; continuous fields (green) create axes and colour gradients. Dates can be either: discrete YEAR gives "2023, 2024" headers, continuous MONTH gives a timeline.

Q: .twb vs .twbx vs .hyper? .twb is the workbook definition without data; .twbx packages the workbook with its data or extract; .hyper is the extract file itself.

Q: Live connection or extract? Live always shows current data but depends on the source's speed; an extract is a fast, compressed snapshot that you refresh on a schedule. Use extracts for speed and offline work, live for real-time needs or very large governed warehouses.

Dual-axis and combo charts

Show two measures with different scales, e.g. Sales as bars and Profit margin as a line:

  1. Continuous MONTH(Order Date) on Columns; SUM(Sales) and the margin calculation on Rows.
  2. Right-click the second pill → Dual Axis. Set the Marks card for Sales to Bar and for margin to Line.
  3. Right-click the right axis → Synchronize Axis only when both measures share units (Sales and Profit); never synchronise ₹ with %.

A blended axis (drag a second measure onto the existing axis until the double-ruler icon shows) puts two measures with the same unit on one axis, using Measure Names on Color.

Bullet chart (actual vs target)

Select a measure and a target (e.g. Sales and a target field) → Show Me → Bullet graph. The bar is the actual, the reference line is the target, and the shaded bands are % of target (60%, 80%). If the bars and lines come out the wrong way round, right-click the axis → Swap Reference Line Fields.

Pareto chart (80/20)

Step by stepBuild a Pareto of products
  1. Product Name on Columns sorted by SUM(Sales) descending; SUM(Sales) on Rows as bars.
  2. Drag SUM(Sales) to Rows again → Quick Table Calculation → Running Total, then Edit Table Calculation → Add secondary calculation → Percent of Total.
  3. Make it dual axis; set the second mark to Line; add a reference line at 80%.
  4. Optional: replace Product Name on Columns with a table calc INDEX()/SIZE() so the x-axis reads "% of products".
Python
p = df.groupby("product_name").sales.sum().sort_values(ascending=False)
cum = p.cumsum() / p.sum()
n80 = int((cum < .8).sum()) + 1
print(f"{n80} of {len(p)} products ({n80 / len(p):.0%}) make 80% of sales")
Output
21 of 78 products (27%) make 80% of sales

Sales are concentrated: about a quarter of the products bring in 80% of sales, close to the classic 80/20 rule. Those top products deserve the best stock availability and marketing. A Pareto chart shows how concentrated a business really is, so you can judge whether a "focus on the top products" strategy makes sense.

Interview cornerQuestions you may be asked

Q: Dual axis vs blended axis? A dual axis gives two independent axes (left and right) and allows different mark types; a blended axis puts several measures on one shared axis (same unit) using Measure Names/Values.

Q: How do you build a Pareto chart in Tableau? Sort the dimension by the measure, show bars, add the measure again with a Running Total table calculation and a secondary Percent of Total, make it dual axis as a line, and add an 80% reference line.

Q: Filled map or symbol map? Filled maps suit rates and ratios (profit margin by state) because area does not scale with value; symbol maps with size suit totals (sales by city).

Row-level vs aggregate: the profit-margin trap

The most common beginner bug in Tableau (and Power BI) is averaging ratios.

Calculated field Formula What it means
Margin (row) [Profit] / [Sales] Margin of each order line; in the view it becomes SUM or AVG of those ratios: wrong
Margin (aggregate) SUM([Profit]) / SUM([Sales]) Total profit ÷ total sales for whatever the mark represents: right
Python
by_cat = df.groupby("category").apply(lambda g: pd.Series({
    "aggregate margin %": g.profit.sum() / g.sales.sum() * 100,
    "average of row margins %": (g.profit / g.sales).mean() * 100}), include_groups=False)
by_cat.round(2)
Output
aggregate margin % average of row margins %
category
Furniture -2.35 -2.38
Office Supplies 14.95 13.76
Technology 11.29 9.95
3 rows × 2 columns

The two columns differ because the average of row ratios gives a ₹500 order the same weight as a ₹5 lakh order. Format the aggregate field as a percentage (right-click → Default Properties → Number Format → Percentage).

Compute Using (addressing and partitioning)

Compute Using tells Tableau the direction of the calculation. Fields it computes along are addressing fields; the remaining fields partition the view into separate calculations. Example: Category on Rows, MONTH on Columns, Running Total of Sales:

  • Compute Using Table (across) → running total along months, restarting for each category (partitioned by Category).
  • Compute Using Table (down) → running total down the categories within each month.
Python
m = df[df.order_date.dt.year == 2025].assign(month=lambda x: x.order_date.dt.to_period("M"))
t = m.pivot_table(index="category", columns="month", values="sales", aggfunc="sum") / 1e5
running = t.cumsum(axis=1)              # Table (across): restarts per category
print(running.iloc[:, [0, 1, 2, -1]].round(1))
share = t.sum(axis=1) / t.values.sum() * 100   # Percent of Total, Table (down)
print((share).round(1).to_dict())

Order of operations

Filters and calculations run in a fixed order. This explains most "why did my number not change?" questions:

TipMake a FIXED LOD respect a filter

A FIXED LOD is computed before dimension filters, so filtering Region does not change {FIXED [Customer ID] : MIN([Order Date])}. To make it respect the filter, right-click the filter → Add to Context.

Summary

Key takeaways
  • Row-level calculations run per row; aggregate calculations run on marks: compute margins as SUM/SUM.
  • Table calculations work on the view's numbers; Compute Using sets the direction (addressing) and the restart points (partitioning).
  • FIXED sets an exact level; INCLUDE adds a level; EXCLUDE removes one.
  • FIXED LODs run before dimension filters; use context filters when they must respect a filter.

Interview cornerQuestions you may be asked

Q: Explain FIXED, INCLUDE and EXCLUDE. FIXED aggregates at exactly the listed dimensions, ignoring the view; INCLUDE adds dimensions to the view's level (finer), then the result is re-aggregated; EXCLUDE removes dimensions from the view's level (coarser). FIXED runs before dimension filters; INCLUDE and EXCLUDE run after them.

Q: Table calculation vs LOD expression? A table calculation runs last, on the aggregated numbers in the view, and depends on layout (Compute Using). An LOD runs in the data source query at a level you define and can be used as a dimension, e.g. for cohorts.

Q: Why might a running total be wrong? Usually Compute Using: it is computing along the wrong field, or a dimension is partitioning it. Check Edit Table Calculation → Specific Dimensions and the sort order.

NoteGroups vs sets

A group combines members into new categories (many buckets, fixed). A set splits a dimension into IN/OUT, can be dynamic (conditional or Top N) and can be changed by users with set actions.

Why joins can inflate totals

A join merges tables before aggregation. If a table on one side has several matching rows, the other side's rows are repeated, and SUM counts them more than once. Relationships avoid this because each table is aggregated at its own level before combining.

Python
# A targets table at territory + year level (one row per territory per year), related to line-level sales
fact["year"] = pd.to_datetime(fact.order_date).dt.year
targets = fact[["territory_key", "year"]].drop_duplicates().assign(target=10_00_00_000)   # ₹10 crore each
joined = fact.merge(targets, on=["territory_key", "year"])                                 # physical join at line level
print("territories x years:", len(targets), "| sales lines:", len(fact))
print("true total target: ₹", f"{targets.target.sum():,}")
print("SUM(target) after a row-level join: ₹", f"{joined.target.sum():,}")
print("inflation factor:", round(joined.target.sum() / targets.target.sum()), "x")
Output
territories x years: 18 | sales lines: 9000
true total target: ₹ 1,800,000,000
SUM(target) after a row-level join: ₹ 900,000,000,000
inflation factor: 500 x

The join repeats each territory's target once per sales line, so SUM(target) is wildly overstated. With a relationship between the sales table and a targets table on territory and year, Tableau aggregates targets at their own level and the total is correct.

Q: Relationships vs joins in Tableau? People read a screen in a Z-pattern: top-left first. Put the KPI cards across the top, the main trend or map in the middle, and the detail (tables, Top N) at the bottom. Keep to about 5–7 views and one colour meaning per dashboard (for example orange = loss everywhere).

KPI cards

Each card is a sheet: the measure on Text, Mark type Text, a formatted label such as ₹<SUM(Sales)> cr, and a small YoY calculation in the second line with ▲/▼ and colour.

Python
import pandas as pd, numpy as np
df = pd.read_csv("superstore_sales.csv", parse_dates=["order_date"])
y = df.groupby(df.order_date.dt.year).agg(sales=("sales", "sum"), profit=("profit", "sum"), orders=("order_id", "nunique"), customers=("customer_id", "nunique"))
cur, prev = y.loc[2025], y.loc[2024]
for k in y.columns:
    unit = 1e7 if k in ("sales", "profit") else 1
    val = f"₹{cur[k] / unit:,.2f} cr" if unit > 1 else f"{cur[k]:,.0f}"
    print(f"{k:10s} 2025: {val:>12s}   YoY {cur[k] / prev[k] - 1:+.1%}")
print(f"margin     2025: {cur.profit / cur.sales:.1%}   (2024: {prev.profit / prev.sales:.1%})")

Dashboard actions

Dashboard → Actions → Add Action:

Action What happens Example
Filter Clicking a mark filters other sheets Click a state on the map → the bar charts show only that state
Highlight Matching marks stay bright, others fade Hover a category to highlight it everywhere
Go to Sheet Navigates to another dashboard Click a KPI to open a detail page
URL Opens a web page, with field values in the link Open a product page or a Google search for the customer
Change Parameter Clicking sets a parameter value Click a region to set the "Selected region" parameter used in titles
Change Set Values Clicking adds/removes marks from a set Drill-in: show sub-categories only for the clicked category (set on a calculation)

Choose Run action on: Select / Hover / Menu and what happens when clearing the selection (show all values is the usual choice). Use Use as Filter (the funnel icon on a sheet) for the quick version.

TipThe "drill-in" pattern with a set action

Create a set on Category; a calculation IF [Category Set] THEN [Sub-Category] ELSE [Category] END on Rows; a Change Set Values action targeting the set. Clicking a category expands it to its sub-categories in the same chart, and clicking again collapses it.

Stories

A Story is a sequence of Story Points, each a captioned snapshot of a sheet or dashboard with its filters. Use it for a presentation: "1. Sales grew 20% in 2025 → 2. Growth came from Technology in the South → 3. Tables and Bookcases lose money → 4. Recommendation".

Interview cornerQuestions you may be asked

Q: How do you design a dashboard for executives? Start from their decisions: 3–5 KPIs with comparisons at the top, one trend, one breakdown, one exception list; consistent colours; filters applied to all sheets; tooltips that explain; a phone layout; and a short written insight.

Q: Filter action vs highlight action? A filter action removes non-selected data from target sheets; a highlight action keeps all data but fades the non-matching marks, preserving context.

Q: How do you share a Tableau dashboard securely? Publish to Tableau Cloud or Server with project permissions, use row-level security (user filters or entitlement tables with USERNAME()), schedule extract refreshes, and share via links, subscriptions or embedding with authentication. Never use Tableau Public for confidential data.
